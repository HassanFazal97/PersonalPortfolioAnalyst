# Cirvia mobile

React Native (Expo) client for iOS and Android. Consumes the same FastAPI
backend as the web app, unchanged. Plan and rationale: [`docs/MOBILE_APP_PLAN.md`](../docs/MOBILE_APP_PLAN.md).

This directory is **not** an npm workspace and is excluded from the Docker
build context — the Python repo's build is untouched by anything here.

## Running it

```sh
cd mobile
cp .env.example .env          # already generated locally; see below
npx expo start --dev-client
```

`react-native-mmkv`, `expo-secure-store`, and `react-native-svg` are native
modules, so **Expo Go will not run this app**. You need a development build:

```sh
npx expo run:ios              # or run:android
```

### Running without paying Apple

The **iOS Simulator needs no Apple account at all** — no team, no
provisioning, no entitlements. It exercises everything except push delivery
and universal links, both of which require the paid Developer Program
regardless. Install Xcode (free) and `npx expo run:ios`.

For a **physical iPhone on a free Apple ID** ("Personal Team"), two
capabilities have to come out first or provisioning fails outright — Xcode
cannot issue a profile for an entitlement the team does not hold:

```sh
EXPO_FREE_BUILD=1 npx expo run:ios --device
```

`app.config.js` layers over `app.json` and, under that flag, drops
`associatedDomains` and the `expo-notifications` plugin (which always sets the
APNs entitlement), renames the app to "Cirvia (free)", and moves the bundle id
to `ca.cirvia.app.free` — a personal team that claims `ca.cirvia.app` can block
registering the same id under the real team later. The client reads
`extra.freeBuild` and skips push registration and the priming screen entirely,
so the one permission prompt iOS grants is not spent on a build that cannot
receive anything.

The free build keeps the `cirvia://` scheme, so the SnapTrade and Discord
round-trips behave exactly as in production — URL schemes need no entitlement.
Profiles expire after 7 days; re-run the command to re-sign.

**Android is unrestricted**: a free emulator or your own phone runs the whole
app including real push, since Expo delivers through FCM. Google Play is $25
one-time, and only when you publish.

`ios/` and `android/` are generated by prebuild and are gitignored; never edit
them by hand, and never eject — the config plugins in `app.json` are the source
of truth.

### Environment

`.env` is gitignored and holds three public values (see `.env.example`). Both
Supabase values match `SUPABASE_URL` / `SUPABASE_ANON_KEY` in the repo-root
`.env`; the anon key is a publishable key the web app already ships in every
page. Metro inlines `EXPO_PUBLIC_*` at build time, so restart the dev server
after changing them.

To point at a local backend, set `EXPO_PUBLIC_API_BASE=http://<your-lan-ip>:8000`
— a phone cannot reach `localhost`.

## Layout

```
app/                    expo-router route tree (file = route)
  (auth)/sign-in        email + password, session in the keychain
  (tabs)/               Digest · News · Holdings · Watching
src/
  api/                  client, ETag cache, query setup, server types
  auth/                 Supabase client and session provider
  dashboard/            portfolio maths, banner rules, the allocation donut
  theme/tokens.ts       the web design system, ported
  ui/                   the primitive layer — screens import from here
```

## Conventions

**Primitives first.** Screens compose `@/ui`; they do not reach for bare
`View`/`Text` or invent one-off styles. This is what keeps a screen at 150–250
lines instead of 600.

**Tokens only.** No literal colours or spacing in a screen. `src/theme/tokens.ts`
is a 1:1 port of the `:root` block in `app/landing.py`, converted from oklch to
sRGB (React Native cannot parse `oklch()`). When a token changes on the web,
re-run the conversion rather than eyeballing a replacement.

**Shared logic goes server-side.** Native lags web by a release, so anything
both clients need — banner conditions, trial state, quota copy, gating — is
computed once on the server and shipped as a flag. `/dashboard/bootstrap` is
the model.

**Check the versioned docs.** Expo's API surface moves between SDKs; see
[`AGENTS.md`](AGENTS.md). SDK 57 already caught us once — `SplashScreen` is no
longer exported from `expo-router`, and `react-native-mmkv` v4 replaced
`new MMKV()` with `createMMKV()` and `delete()` with `remove()`.

## Status

M0 (foundations), the M1 dashboard slice, and M2 (streaming chat) are in:
sign-in, the four dashboard tabs, the ETag/MMKV cache layer, the primitive
layer, and the chat modal.

Chat uses the native pair — `POST /chat/start` then
`GET /chat/runs/{id}/events` — not the web's `POST /chat/stream`, which React
Native cannot consume (no readable stream body on `fetch`, and `EventSource`
can neither POST nor set an `Authorization` header). The run id is persisted to
MMKV the moment it is known and re-subscribed on foreground, so an answer that
finishes while iOS has the app suspended is recovered instead of lost. Fallback
chain: SSE → `GET /runs/{id}`.

M3 (stock detail) is in too: the ported price chart with a touch-and-hold
crosshair, the four range toggles, position, valuation verdict with its
Pro-gated evidence table, price action, and per-ticker news. The 1D range
re-fetches every 60s to match the server's intraday cache TTL; the other
ranges are static.

M4 (onboarding) is in: the seven-step flow, the SnapTrade auth session with
its status poll, the manual-holdings fallback, and delivery setup with code
verification.

M5 (settings) is in: account and digest schedule, brokerage status with
reconnect and sync, delivery with channel verification and native Discord
connect, the status-only plan screen, and account deletion.

The only server change the client needed is an `app` return target in
`app/delivery/discord_connect.py`, which bounces the OAuth callback to
`cirvia://settings/delivery` — redirecting to the app's scheme is what closes
the auth session and hands control back. It is a literal in the existing
allowlist, so it opens no redirect surface.

M6 (push) and M7 (deep dives, picks) are in.

**Push is a fan-out, not a fourth channel.** `preferred_channel` resolves one
destination, so making push selectable would silently take away a user's email
digest. Instead `enqueue_outbound(push=True, …)` writes one extra
`outbound_messages` row per registered device, alongside whatever the
preferred channel does, and the delivery picker filters `push` out of
`available_channels` so it can never be chosen.

**Push ships dry-run first.** `PUSH_DRY_RUN` defaults to true: rows are queued
and the adapter logs what it would send, without a notification reaching a
phone. That is deliberate — the fan-out edits the one function whose silent
failure means nobody gets their digest. Turn it off only after the queued rows
have been observed in production.

The permission prompt fires from `app/push-priming.tsx` after the first
successful sync, never at launch: it is a one-shot resource, and spending it
on a user with no portfolio is how an install base ends up permanently muted.

M8 is partly in: universal links / App Links (served from
`/.well-known/*` and templated from config), the iOS privacy manifest and
associated domains, offline states, the a11y sweep, and the review-account
seeder (`scripts/seed_review_account.py`).

### Icons

`assets/*.png` are generated, not hand-drawn: run

```sh
python mobile/scripts/make_icons.py
```

The mark is a thick ring with a wedge cut from its right side and a dot
centred in that aperture — the allocation donut that is the product's
signature visual, which also reads as a C. Colours are the shipped tokens.

The script writes PNGs with stdlib `zlib` and rasterises from a signed-distance
field, so no image library enters this repo's hash-pinned lockfile. It prints
an ASCII silhouette so the shape can be checked without opening a file. Edit
the constants at the top and re-run rather than editing the PNGs.

Verified: `icon.png` is fully opaque (Apple rejects any transparency in an app
icon), the Android foreground fills 91% of the safe circle the launcher never
crops, and the aperture stays ≥18° wide so the C does not close up into an O
at tab-bar size.

### Dark mode: not shipping in v1

`userInterfaceStyle` is pinned to `light`, deliberately. Doing dark mode
properly means turning `theme/tokens.ts` into a light/dark pair behind a hook
and converting every `StyleSheet.create` to read from it — a refactor across
~45 files. Half-done (some screens dark, some light) is worse than light-only,
which is a defensible v1 for a finance app.

### Shipping to the stores

`eas.json` holds the build profiles. The two Supabase values are NOT in it:
`.env` is gitignored and EAS cloud builds never see it, so set them once as
EAS secrets or the build produces an app that cannot sign in.

```sh
eas secret:create --scope project --name EXPO_PUBLIC_SUPABASE_URL --value "https://<ref>.supabase.co"
eas secret:create --scope project --name EXPO_PUBLIC_SUPABASE_ANON_KEY --value "sb_publishable_..."
```

`EXPO_PUBLIC_API_BASE` is a plain public hostname and lives in `eas.json`
directly. The three `REPLACE_WITH_*` fields under `submit.production.ios`
need filling before `eas submit` will run.

### Before submitting

`IOS_TEAM_ID` and `ANDROID_CERT_FINGERPRINTS` must be set in Railway or both
`.well-known` routes 404 by design — and universal links then fail *silently*,
opening every link in the browser instead of the app.

**First TestFlight build is now possible** — sign-in, dashboard, chat, and
stock detail are the cut the plan names as the one that exercises every
architectural piece (auth, ETag/SWR, SSE, SVG) on a real device.
